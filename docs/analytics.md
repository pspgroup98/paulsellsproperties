# Analytics Setup and Event Reference

## Overview

paulsellsproperties.com uses two analytics services:

- **Google Analytics 4 (GA4)** — usage analytics (page views, sessions, events)
- **Microsoft Clarity** — session recordings and heatmaps

Neither service is configured for advertising purposes. Both respect the opt-out
preference stored in the visitor's browser.

---

## Setup Checklist

Before analytics data is collected, two IDs must be configured:

### 1. Google Analytics 4

1. Go to [analytics.google.com](https://analytics.google.com)
2. Create a property for paulsellsproperties.com
3. Set up a Web data stream for `https://paulsellsproperties.com`
4. Copy the Measurement ID (format: `G-XXXXXXXXXX`)
5. Open `assets/js/analytics.js` and replace `G-XXXXXXXXXX` with your real ID
6. In GA4 Admin, set data retention to **14 months** (Admin > Data Settings > Data Retention)
7. In GA4 Admin, disable Google Signals (Admin > Data Settings > Data Collection — turn off Google Signals)

### 2. Microsoft Clarity

1. Go to [clarity.microsoft.com](https://clarity.microsoft.com)
2. Create a new project for paulsellsproperties.com
3. Copy the Project ID (10-character alphanumeric string)
4. Open `assets/js/analytics.js` and replace `xxxxxxxxxx` with your real Clarity ID

### 3. Google Search Console

1. Go to [search.google.com/search-console](https://search.google.com/search-console)
2. Add property `https://paulsellsproperties.com`
3. Choose verification method: **HTML tag**
4. Copy the `content="..."` value from the meta tag shown
5. Open `index.html`, find the commented-out GSC tag near the `<link rel="canonical">` line
6. Uncomment it and replace `YOUR_VERIFICATION_TOKEN` with the copied value
7. Commit and push, then click Verify in Search Console

## Consent Model

Analytics load by default (opt-out model). California law does not require explicit
opt-in consent for basic analytics on small business websites not subject to
CCPA/CPRA thresholds. Visitors can opt out at any time via the "Privacy Policy"
footer link → "Manage Analytics Preferences" button.

The preference is stored in `localStorage` under the key `psp_analytics`:
- `"granted"` (default) — analytics load normally
- `"denied"` — GA4 and Clarity scripts are not loaded

---

## GA4 Configuration

Advertising features are disabled:
- `allow_google_signals: false`
- `allow_ad_personalization_signals: false`
- `ad_storage: "denied"` (GA4 consent mode)
- `ad_user_data: "denied"`
- `ad_personalization: "denied"`

IP anonymization: GA4 4.x does not store raw IP addresses (this is GA4's default).

## Event Reference

All custom events use `window.PSP.track(eventName, params)` via `assets/js/analytics.js`.

| Event | Trigger | Parameters |
|-------|---------|-----------|
| `article_view` | Blog article page load | `article_slug`, `article_category`, `article_type` |
| `scroll` | 25%, 50%, 75%, 90% scroll depth | `percent_scrolled` |
| `cta_click` | Any element with `data-track-click="cta_click"` | `data-track-params` value |
| `form_start` | First focus on a form field | `form_name` |
| `form_submit` | Form submit event | `form_name` |
| `form_error` | Form submission error (call manually) | `form_name`, `error_type` |
| `contact_method_click` | Click on `mailto:` or `tel:` link | `method` ("email" or "phone") |
| `calendly_trigger` | Calendly popup opened via `PSP.openCalendly()` | `calendly_url` |
| `outbound_link` | Click on external link | `link_url`, `link_domain` |

Auto-tracked by GA4 (no custom code needed):
- `page_view` — every page load
- `session_start` — new session
- `first_visit` — first time the visitor visits

## Adding Custom CTA Events via HTML Attributes

Any element can be instrumented without JavaScript by adding data attributes:

```html
<button
  data-track-click="cta_click"
  data-track-params='{"cta": "schedule_consultation", "location": "hero"}'>
  Schedule a Consultation
</button>
```

`analytics.js` scans for `[data-track-click]` on `DOMContentLoaded` and attaches handlers.

## Form Tracking

To add form analytics to any page:

```javascript
// After DOMContentLoaded
document.addEventListener('DOMContentLoaded', function () {
  var form = document.getElementById('yourFormId');
  PSP.trackForm(form, 'contact_form'); // second arg is the form_name sent to GA4
});
```

**Important:** Never pass form field values (email, name, phone, message) to `trackForm()`.
Only the form identifier string is passed.

## UTM Parameter Tracking

GA4 automatically reads `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`,
and `utm_term` from URL parameters. All social content posts use the UTM URLs
generated by the editorial batch package.

Example:
```
https://paulsellsproperties.com/blog/buying-rso-property-los-angeles.html
  ?utm_source=instagram
  &utm_medium=carousel
  &utm_campaign=buying-rso-property-los-angeles
```

---

## What Is Never Sent to Analytics

- Names, email addresses, phone numbers
- Form field content of any kind
- Private property addresses entered by users
- Financial, income, or account information
- Calendly booking details
- Authentication credentials

These exclusions are enforced by the design of `analytics.js` — form field values
are never passed to any tracking function.
